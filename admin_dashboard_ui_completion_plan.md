# UI Completion Plan: Frontend Admin Dashboard Enhancement

This document outlines the comprehensive UI completion and enhancement plan for the Frontend Admin Dashboard of the Warehouse Management System, mapping current capabilities against required backend integrations.

---

## 1. Existing Admin Dashboard Analysis (Step 1)

An inspection of the frontend React source code indicates a fully client-side mock framework with the following breakdown:

### Existing UI Components
*   **KPI Cards Grid** (`AdminDashboard.jsx`): Houses stat summaries for Registered Users, Active Users, Security Roles, Sessions, Failed Retries, Service status, Audit logs length, and Access alerts.
*   **Quick Action Links** (`AdminDashboard.jsx`): Redirect icons to users, roles, audits, health, and settings.
*   **User Registry Grid** (`UserManagement.jsx`): Search bar, listing table with columns for Name, Email, Role, Assigned Facility, Activation Status, and Last Sign-In. Contains an edit/provision modal.
*   **Permissions Matrix Table** (`RoleManagement.jsx`): Toggles for user role permissions.
*   **Health Dashboard** (`SystemHealth.jsx`): Mock cards representing database transactional indexes and response rates.
*   **Audit logs** (`AuditLogs.jsx`): Displays logging messages generated by client actions.

### Mock Components (Simulated Actions Only)
*   **Microservice Roster** (`SystemHealth.jsx`): Status rows for API Gateway, CockroachDB, PaddleOCR, ONNX Recommendation, and React Server. All latencies, memory levels, and states are mocked.
*   **Access Control Audits** (`AdminDashboard.jsx`): Static list items detailing SSL TLS and MFA handshakes.
*   **Password Reset** (`UserManagement.jsx`): Button triggers browser alerts without hitting any backend mail dispatcher.
*   **Diagnostics triggers** (`SystemHealth.jsx`): Buttons (AGV RF ping, database reindex, logs download) run local `setTimeout` functions and print mock logs.

### Missing UI Components
*   **Zone Groups & Aisles Pages**: No pages exist for managing Zone Groups and Aisles.
*   **Warehouse Hierarchy Tree**: Lacks a visual tree depicting the nested relationship from Warehouse down to specific Bins.
*   **Admin Reports Hub**: Lacks an analytical reporting view for administrators.

### Unused UI Components
*   **Mock data arrays**: Large offline JSON blocks in `mockData.js` and `WarehouseContext.jsx` that duplicate data structures instead of calling real APIs.

## 3. Warehouse Structure Module (Step 3)

The Admin must have visibility and management endpoints over all structure tiers.

### Layout Pages Review

#### A. Warehouses (`Warehouse.jsx`)
*   **Current UI**: Table showing Name, Location, Area size, active zones, occupancy bar, active staff count, and detail drawer.
*   **Missing Columns**: CAD layout file url link, Width, Height, Depth dimensions.
*   **Missing Actions**: Upload CAD file button, Edit Warehouse parameters, Delete/Deactivate Facility.
*   **Required Filters**: Location filter, status dropdown (operational/maintenance).
*   **Required Search**: Text search on warehouse Name and Location.

#### B. Zone Groups (New Page)
*   **Current UI**: **Missing entirely**.
*   **Required Columns**: Zone Group ID, Name, Warehouse Name, Zones count.
*   **Required Actions**: Add Zone Group, Edit Name, Delete/Disassociate.
*   **Required Filters**: Warehouse facility filter.
*   **Required Search**: Text search on Zone Group Name.

#### C. Zones (`ZonesBins.jsx` - Tab 1)
*   **Current UI**: Table showing Zone Name, Type, Warehouse name, Utilization percent bar, status.
*   **Missing Columns**: Boundary vertices count, x/y/z coordinate offsets.
*   **Missing Actions**: Polygon coordinates visual editor (draw boundary points on layout canvas).
*   **Required Filters**: Warehouse dropdown, Zone Type dropdown.
*   **Required Search**: Text search on Zone Name.

#### D. Aisles (New Page)
*   **Current UI**: **Missing entirely**.
*   **Required Columns**: Aisle ID, Code/Label, Zone Name, Associated Racks count.
*   **Required Actions**: Add Aisle, Edit designation, Delete.
*   **Required Filters**: Zone dropdown, congestion level index.
*   **Required Search**: Text search on Aisle Code.

#### F. Racks (`ZonesBins.jsx` - Tab 2)
*   **Current UI**: Table listing Rack ID, Rack Code, Zone name, Max weight limit, current weight load.
*   **Missing Columns**: 3D coordinates (x, y, z), physical dimensions (width, height, depth), rotation angle, connected shelves count.
*   **Missing Actions**: Slotting rule toggle (configure SKU affinities per rack).
*   **Required Filters**: Zone dropdown, status indicator.
*   **Required Search**: Text search on Rack Code.

#### G. Shelves (`ZonesBins.jsx` - Tab 3)
*   **Current UI**: Table listing Shelf ID, Level (e.g. Level 1), Rack code, weight capacity.
*   **Missing Columns**: Height from ground offset (decimal).
*   **Missing Actions**: Shelf bulk creation modal.
*   **Required Filters**: Rack dropdown.
*   **Required Search**: Text search on Shelf Level.

#### H. Bins (`ZonesBins.jsx` - Tab 4)
*   **Current UI**: Table listing Bin Code, Zone Name, Shelf Level, Max capacity units, weight limit, current product SKU details, status badge.
*   **Missing Columns**: 3D spatial coordinate coordinates, occupied capacity percentage.
*   **Missing Actions**: Product quarantine assignment flag, manual capacity override.
*   **Required Filters**: Shelf dropdown, Occupancy Status (Empty, Partial, Full).
*   **Required Search**: Text search on Bin Code or Assigned SKU.

## 4. Warehouse Structure Viewer (Step 4)

A visual hierarchy panel represents the database layout.

### Recommended Tree View UI Component (`WarehouseTree.jsx`)
*   **Layout Panel**: Positions as a sidebar block or left-hand column inside structure pages.
*   **Expand/Collapse Behavior**:
    *   Root node (Warehouse) defaults to expanded.
    *   Clicking a parent node toggles disclosure arrows and slides open nested children lists.
    *   Double-clicking triggers a "Focus" mode, rendering only that branch's list.
*   **Navigation & Interaction Behavior**:
    *   Clicking any node inside the tree fires a route state callback.
    *   The adjacent list table automatically applies query parameters to show only descendants of the clicked node.
    *   Hovering over nodes shows status indicators (e.g. hovering a Bin node displays a tooltip showing occupied SKU name and current weight).

## 5. User Management Module (Step 5)

The user management console governs access scopes.

### User Workflows review
*   **User List Grid**: Displays user records. Needs pagination and columns for Role and Activation status.
*   **User Details Drawer**: Clicking a user opens a slide-over panel displaying: Full audit log trail, assigned zone efficiencies, security events list, and active session telemetry.
*   **Create / Provision User**: Form supports creating user records.
*   **Edit User Details**: Form allows modifying existing email addresses, assigned warehouses, or roles.
*   **Deactivate User**: Red button changes status from "Active" to "Inactive" via `PATCH /api/users/{id}/`.
*   **Assign Roles**: Dropdown selection maps roles to exact database string values (`ADMIN`, `MANAGER`, `STAFF`, `INVENTORY_CLERK`).

### Required UI Improvements
1.  **MFA Sync indicator**: Visual icon showing if the user has completed multi-factor setup.
2.  **Activity logs integration**: Renders the user's audit logs in a sub-table within their details drawer.

### Layout Components Definition

4.  **Live Action Log (Bottom-Right)**: Streaming grid detailing database audits.
